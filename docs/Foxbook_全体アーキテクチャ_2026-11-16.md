# Foxbook 全体アーキテクチャ

- 作成日: 2026-11-16
- 改訂: 2026-11-16（リポジトリ境界とNative Hostの役割を明確化）
- 状態: 設計案（音声基盤の分離は未実装）
- 対象: Firefoxキオスク環境 Foxbook と関連拡張・Native Messaging Host・ローカルサービス

## 1. 目的と設計原則

Foxbookは、Linux上のFirefoxを中心に、タッチ操作・音声入力・ローカルファイル操作・開発支援・楽譜閲覧を統合する環境である。Firefox拡張はUIと利用目的に固有のロジックを担当し、OS資源へのアクセスは用途を限定したNative Messaging Host経由とする。共有ハードウェアや高コストな処理は必要に応じて独立したローカルサービスへ集約する。

原則:
1. WebページからOS操作へ直接到達できる経路を設けない。
2. 拡張とNative Hostは許可された操作のみを公開する。拡張IDは明示的な許可リストで管理する。
3. 共有機能は共通化し、アプリ固有のUI・履歴・コマンド解釈は利用側に残す。
4. 最小権限、固定設定、明示的な利用開始、失敗時の安全な停止を優先する。
5. 既存の拡張間契約を維持し、段階的に移行する。

## 2. リポジトリ単位の構成（移行後の目標）

**音声認識に関係する実装は2リポジトリに分ける。** `foxbook-speech` はリポジトリ名であり、Native Hostやserviceと同じ階層の実行コンポーネントではない。図の枠はソースコードの所有先を表す。

```text
Linux / Fedora / Cage
└─ Firefox
   ├─ 【リポジトリ: fox-voice-editor】
   │   ├─ Fox Voice Editor（Firefox拡張）
   │   │    ├─ 録音UI、認識テキスト編集、ブロック挿入
   │   │    ├─ 履歴・定型文のUI、Focodex/OSK連携
   │   │    ├── Native Messaging ──→ fox_voice_editor Host
   │   │    │                           └─ 編集固有データの保存・読込
   │   │    └── Native Messaging ────────────────┐
   │   └─ fox_voice_editor Native Host            │
   │        （編集固有の保存処理のみ）                │
   │                                               │
   ├─ THE SESSION TOOLS（別リポジトリ、将来利用）──┤
   └─ その他の許可済み拡張（将来利用）──────────────┤
                                                   │
【リポジトリ: foxbook-speech】                      │
   ├─ foxbook_speech Native Messaging Host ◀──────┘
   │    ├─ Firefox Native Messaging入出力
   │    ├─ 許可済み拡張との接続・入力検証
   │    └─ Unix domain socket経由の中継
   │                     │
   ├─ foxbook-speech service ◀───────────────────┘
   │    ├─ マイク使用状態・要求調停・録音/変換
   │    ├─ Whisper CLI / ReazonSpeech worker・モデル管理
   │    ├─ 取消・タイムアウト・一時ファイル管理
   │    └─ 端末別マイク補正
   ├─ systemd --user 設定（常駐/ソケット起動は未決定）
   └─ 共通音声API仕様・導入手順・テスト
```

※ 図は依存関係の概念図。実際の通信は **Firefox拡張 → foxbook_speech Native Host → Unix socket → foxbook-speech service → Host → 拡張** の往復。編集データは別経路で `fox_voice_editor` Hostに送る。共通Hostは登録名・コードが一つでも、Native Messaging接続ごとにプロセスが起動する。

### リポジトリの責務（確定した方向性）

| リポジトリ | 所有するもの | 所有しないもの |
|---|---|---|
| **fox-voice-editor** | Firefox拡張（録音UI、認識結果編集、ブロック挿入、履歴・定型文、Focodex/OSK連携）、**編集専用** `fox_voice_editor` Native Host | 録音実行、認識エンジン実行、モデル管理、共通マイク排他 |
| **foxbook-speech** | **共通** `foxbook_speech` Native Messaging Host、**単一の論理サービス**、Whisper/ReazonSpeech管理、録音/マイク管理、systemd設定、共通音声API仕様 | 編集履歴・定型文、認識後のコマンド解釈、Focodex/OSK固有処理 |
| **foxbook** | 全体連携仕様、採用方針、統合・運用文書 | 音声認識の実装本体 |

### Native Messaging Hostが2種類ある理由

`fox_voice_editor` は**Voice Editor専用の編集データ管理窓口**。`foxbook_speech` は**複数拡張が使う音声認識の共通窓口**。両方ともFirefoxから接続されるが、互いを経由する必要はない。したがってFox Voice Editorは移行後、用途別に2つのHostへ接続する。新しい音声利用拡張は `foxbook_speech` だけを利用できる。

### Foxbookのその他の構成要素

Focodex、FX-OSK、LATO、Setoli、Foxbook Control、Split View等は引き続きそれぞれの責務を維持する。音声基盤の共通化は、端末制御やファイルアクセスのHostまで統合することを意味しない。

## 3. コンポーネントの責務（実装単位）

| コンポーネント | 所属リポジトリ | 移行後の役割 |
|---|---|---|
| Fox Voice Editor拡張 | fox-voice-editor | 録音開始/停止UI、認識テキスト編集、履歴・定型文UI、Focodex/OSK連携。共通音声APIを呼ぶ |
| `fox_voice_editor` Native Host | fox-voice-editor | 編集固有のライブラリ保存・読込。**録音・認識の実行処理は持たない** |
| `foxbook_speech` Native Host | foxbook-speech | Native Messagingプロトコル、要求検証、Unix socketへの軽量中継。**認識モデルはロードしない** |
| `foxbook-speech service` | foxbook-speech | 録音・マイク調停・音声認識・モデル管理・結果返却の実行主体 |
| systemd設定・共通API仕様 | foxbook-speech | サービス起動・停止・接続と公開契約を管理 |
| THE SESSION TOOLS | 別リポジトリ | 将来、共通APIから認識テキストを受け取り、BPM等のコマンドを自分で解釈 |
| foxbook | foxbook | 横断設計の記録、導入・統合ルール |

## 4. 音声認識の現状と変更案

### 現状（実装済み）

```text
Fox Voice Editor拡張
  → connectNative("fox_voice_editor")
  → 専用Native Host（接続ごとにプロセス）
  → arecord / ffmpeg
  → whisper-cli または ReazonSpeech worker
  → 認識テキストを編集UIへ
```

現状のHostには、30秒の録音上限、停止・取消・切断時の一時ファイル削除、マイク補正、エンジン実行・タイムアウト、履歴・定型文の永続化が混在する。拡張側では `recordingId` とエンジン世代を照合する。

### 計画（未実装）

```text
各許可済みFirefox拡張
  → connectNative("foxbook_speech")
  → 接続ごとに起動する軽量Native Hostアダプター
  → Unix domain socket
  → 共有音声サービス
  → マイク・認識エンジン
  → 要求元へ結果返却
```

**注意:** 共通音声Hostの名前・登録ファイル・実装を一つにしても、Native Messagingの接続ごとにHostプロセスが起動する。マイク状態やモデルの共有には別のサービスが必要。サービスはsystemd --userで管理する想定とし、常駐かソケット起動かは実測で選択する。

## 5. 音声APIの責務と境界

共通基盤は「音声を認識してテキストを返す」ことまでを担当し、自然言語コマンドの解釈や実行は担当しない。

- API v1: `prepare_microphone`、`prepare_engine`、`start_recording`、`stop_recording`、`cancel_recording`、`get_status` と結果・状態イベント。詳細なキーと状態遷移はfoxbook-speech仕様書を正本とする。
- 識別子はプロトコル版、service発行の`recordingId`、エンジン世代を用いる。接続単位の識別子はservice内部だけで管理する。
- 録音・認識の状態遷移、切断・タイムアウト時の解放、重複・古い結果の排除を仕様化済みである。
- 拡張から任意コマンド、実行ファイル、モデルパス、音声ファイルパスを受け付けない。
- `load_library` / `save_library` は音声APIに含めない。
- 同時要求は初期段階では明示的な `BUSY` 応答などで直列化する。将来、ウェイクワード監視と通常録音の共存が必要になった場合は、マイク共有・音声ストリーム配信の設計を再検討する。
- `clientId` はAPIで受理しない。Native Hostの許可設定、adapterの起動元ID検証、ローカルsocket sessionで要求元を対応付ける。

### 実装判断（2026-11-16）

- 接続所有権は、Firefoxが起動したadapterのHost接続と、adapterが開く一つのUnix socket sessionで決める。`clientId`はAPIへ含めず、`recordingId`の停止・取消・イベント配送は所有sessionだけに限定する。
- `start_recording`から結果・エラー・取消までを一件のグローバル録音リースとし、録音・変換・認識中の新規開始は待ち行列に入れず`BUSY`で拒否する。socket切断、Host終了、service停止、タイムアウトもリースの回収条件とする。
- Whisperは要求ごとのCLI実行、ReazonSpeechはengine名とモデル設定revisionごとの最大一つのservice Workerとする。利用者ごとのengine切替は他利用者のWorkerを停止しない。
- Voice Editorは`foxbook_speech`への`speechPort`と、編集履歴・定型文を保存する`fox_voice_editor`への`libraryPort`を分離する。詳細は[foxbook-speech仕様書v0.1](../../foxbook-speech/specification/foxbook-speech仕様書v0.1.md)を正本とする。

### 利用例

```text
THE SESSION TOOLS: 「メトロノーム150」
  → foxbook-speech: 音声を「メトロノーム150」として返却
  → THE SESSION TOOLS: コマンド解析、BPM=150を設定

Fox Voice Editor: 長文の発話
  → foxbook-speech: 認識テキストを返却
  → Fox Voice Editor: ブロック挿入、履歴保存、必要ならFocodexへ送信
```

音声アシスタントの共通コマンドルーターやウェイクワード検出は**将来構想**であり、今回の音声認識共通化の必須要件ではない。

## 6. マイク・モデル・性能

- 初期版はサービスが録音要求を一元管理し、同時録音を許さない設計を基本とする。
- ALSA/PipeWireの構成によっては物理マイクの同時オープン自体は可能。排他はハードウェア制約の断定ではなくFoxbookのUX・処理制御ポリシーである。
- ReazonSpeechは可能な範囲でworkerとモデルを再利用し、多重ロードを避ける。Whisper CLIは要求ごとの起動を基本候補とする。
- Surface Pro 4（8GB）を考慮し、モデル常駐・アイドル解放・初回起動時間・メモリ使用量を実測する。
- マイク補正は端末依存設定として分離し、他端末でSurface固有処理を誤実行しない。

## 7. セキュリティと運用

1. Native Messaging manifestの `allowed_extensions` に固定の許可済み拡張IDのみを列挙する。
2. Native Hostは入力形式・サイズ・操作種別を検証し、IPCを必要なローカルユーザーに限定する。
3. WebページのスクリプトからNative Hostへ直接命令できない構成を維持する。拡張のページ連携にも明示的な制約を設ける。
4. マイク使用開始は利用者操作を基本とし、UIで録音状態を表示する。チューナー等のマイク使用はパネル切替時など用途に応じて明示する。
5. 録音データは原則一時保存し、停止・取消・切断・異常時に削除する。ログへ音声や認識全文を不用意に残さない。
6. サービス停止・Host切断・拡張再読み込みで、録音リースやworkerが取り残されないようにする。
7. Native Messaging Hostは共通化しても、端末制御・ファイル操作等の別権限まで音声Hostに統合しない。

## 8. 既存機能との互換性

- 移行中は既存JSON契約を変換する互換層を設けてもよい。ただし**移行後の最終構成ではVoice Editor拡張が共通 `foxbook_speech` Hostへ直接接続**し、編集専用 `fox_voice_editor` Hostとは用途別に使い分ける。互換層を恒久的な第3のHostにしない。
- `prepare_microphone`, `start_recording`, `stop_recording`, `cancel_recording` の既存挙動とエラー形式を確認する。
- 編集履歴・定型文・schema移行はVoice Editor固有の機能として維持する。
- Focodexへの文章配送、FX-OSK、Split Viewの既存メッセージ契約は原則変更しない。
- 既存 `fox_voice_editor` Hostの**音声認識機能のみ撤去**する。編集固有データ管理が必要な間はHost自体を維持する。

## 9. 段階的な移行計画

1. **仕様確定:** 共通API、状態遷移、IPC、権限、端末設定、エラーと互換条件を文書化する。
2. **サービス分離:** 新リポジトリ `foxbook-speech` に録音・変換・認識・モデル管理を実装する。
3. **互換接続:** 移行中は従来契約の変換層を用いてよい。最終的にVoice Editor拡張の音声操作を `foxbook_speech` Hostへ接続し、編集データ操作のみ `fox_voice_editor` Hostに残す。
4. **回帰テスト:** 単独録音、停止・取消、タブ終了、拡張再読み込み、Host/サービス異常終了、二重要求、モデル再利用、Surfaceマイク補正を検証する。
5. **新規利用者:** THE SESSION TOOLS等から短いコマンド認識を呼び出して汎用性を検証する。
6. **整理:** `fox_voice_editor` Hostから録音・認識処理を撤去し、編集専用に縮小する。仕様書・インストール手順・依存関係を更新する。

## 10. 未決定事項

- 正式リポジトリ名、Host名、プロトコルバージョン規則。
- systemd --userの常駐方式かソケットアクティベーション方式か。
- ウェイクワード方式を将来採用するか、その場合のストリーム共有方式。
- Fox Voice Editor固有の永続化は当面既存 `fox_voice_editor` Hostに残す（将来の別方式への移行は今回の範囲外）。

## 11. 設計判断の要約

**決定した方向性:** `fox-voice-editor` は「Firefox拡張＋編集専用Host」、`foxbook-speech` は「共通音声Native Host＋音声サービス＋認識エンジン管理＋systemd設定＋共通API仕様」を所有する。音声認識のNative Messaging Host登録・実装は `foxbook-speech` の一か所に集約し、接続ごとのHostプロセスとは別に共有音声サービスを設ける。共通サービスは録音・認識に専念し、認識結果の解釈・実行は各拡張が担当する。既存のFox Voice Editorを最初の移行対象とする。

**設計案であって未実装:** 共通サービス、API、systemd運用、複数拡張対応、ウェイクワード共存。現状の稼働機能と混同しないこと。
