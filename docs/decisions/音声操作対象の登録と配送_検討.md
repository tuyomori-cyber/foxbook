# 音声操作対象の登録と配送（検討中）

## 初期登録の方針

THE SESSION TOOLSを最初の操作対象として、管理側のコード内にアプリID、Firefox拡張ID、対応するAPIバージョンを固定値として明示的に登録する。値や形式は後から変更できるようにし、初期値と照合規則は決め打ちする。表示名やコマンド定義は登録時に固定せず、`getCommands`で対象から取得する。取得した応答が不正、またはアプリIDやAPIバージョンが登録内容と一致しない場合は、その対象を操作不可とし、理由をイベント表示に記録する。具体的な初期値や応答の検証項目は実装前に定める。

登録解除後は新しい操作を受け付けない。送信済みの操作は解除によって取り消せると保証せず、利用者にその可能性を伝える。表示方法や解除と送信が競合する場合の詳細は未設計。

初期の登録情報はコード内固定値であり、実行中に管理画面から登録解除する機能は未設計。解除と送信の競合をどう制御するかは、解除機能の具体化に合わせて定める。

将来の解除機能では、解除が確定してからの新規操作は送信せず、その理由を表示する。送信後に解除が確定した場合、送信済み操作は取り消せない可能性を表示し、応答を受け取れれば結果も表示する。送信できたか判別できない場合は結果不明とし、自動再送しない。解除確定と送信の順序を管理側で判断できるようにするが、具体的な確定点・制御方法は解除機能の設計時に定める。

## イベント表示

初期段階は管理画面を開いている間、登録・解除、定義取得、操作送信、成功・失敗・結果不明などの主なイベントを時系列で表示する。履歴を保存せず、画面を閉じた後や閉じている間の履歴は確認できない。将来の保存を追加しやすいよう、時刻・種類・対象・結果などの情報と表示用の文章を分ける。要求との対応付けは要求IDの設計に合わせる。保存方式・期間・記録内容は未決定。イベント表示と要求状態の管理は別であり、画面を閉じても送信済み操作の取消は保証しない。

これは操作対象の登録であり、foxbook-speechの利用許可とは独立する。既存の音声基盤の接続・認証は変更しない。上記は設計方針であり、正式な登録機能の実装・検証が完了したことを意味しない。

## 段階的な方針

最初は管理拡張に明示的に登録した拡張IDと期待するアプリIDの組だけに問い合わせる。試作ではコードに固定し、利用者が対象を選択して定義を取得する。定義は毎回対象から取得し、対応する版・アプリID・操作IDを検証してから利用する。取得成功はその時点の応答に限り、インストール状態や後続操作の成功を保証しない。定義中の名前・発話例は表示や照合に用いるデータであり、呼出先IDや許可の根拠にしない。

任意の拡張を走査する自動発見は採用しない。将来の追加は登録内容の提供元、利用者の許可、ID衝突、定義変更、削除・無効化、永続化と悪意ある定義の扱いを設計してから決める。固定IDも正式な認証方式の決定を意味しない。受信側による送信元確認と各操作の入力・状態検証は別途必要である。

## 通信の失敗と再試行

試作は定義取得・操作要求の応答をそれぞれ最大5秒待つ。この値は試作用で正式な性能要件ではない。定義取得が失敗・時間切れならその対象の操作を無効化する。操作要求が通信失敗・時間切れなら実行結果は不明とし、自動再送せず操作を無効化する。利用者が対象の状態を確認した後に定義を再取得し、必要なら改めて操作する。要求中は重複操作と対象切替を防ぐ。

時間切れは送信済み処理をキャンセルしない。遅い応答は表示に反映せず、対象側が後から操作する可能性もある。したがって画面確認や定義の再取得は操作の未実行を保証しない。確実な再試行には対象側の要求ID・重複排除、状態照会と保持期間などの設計が必要で、試作では提供しない。ポップアップを閉じた場合も処理の取消を保証しない。

## 検証と保留

試作の二重送信防止、通信失敗、時間切れと遅延応答の扱いは擬似応答の自動試験で確認する。ダミー対象に遅延・無応答モードと操作記録を追加し、自動試験した。利用者がFirefoxで正常・遅延応答・遅延実行・操作無応答・定義取得無応答の5条件を期待どおりと確認。遅延実行の送信直後に設定ページへ移動しても約8秒後に操作記録が現れた。端末・Firefoxバージョンは未記録。[試験手順](../../../foxbook-speech/assistant-ui/exchange-probe/README.md)を参照。固定IDの変更や正式管理拡張ID、複数対象の自動照合、無効化中からの復帰、接続の長期監視は未設計。定義取得に使うメッセージは一回限りであり、常時接続や切断通知ではない。現行の音声・マイク契約は変更しない。
